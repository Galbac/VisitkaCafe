# Результат аудита — 1 ноября 2026

Проверены исходный код Django/JavaScript, формы, модели и загрузки, настройки безопасности, Docker/Compose/nginx, все пять образов и фактически установленные Python-пакеты. Исправления применены к проекту и локальным контейнерам. Рабочий сервер не изменялся.

## Исправления

| Проблема | Исправление |
| --- | --- |
| Строковое значение DEBUG включало отладку даже при False | Чтение bool, безопасное значение по умолчанию; проверено production-скриптом |
| Запасной известный SECRET_KEY, wildcard ALLOWED_HOSTS | Ключ обязателен; production отвергает слабый ключ и wildcard; хосты по умолчанию локальные |
| Заказы сохранялись без формы, возможны ошибки БД и некорректные значения | ModelForm, диапазон количества, длины, формат телефона, проверка продукта и типов JSON |
| JSON-массивы, вложенные объекты и невалидный JSON вызывали ошибки | Ответ 400 до записи в БД; тесты вложенных типов и CSRF |
| HTML-инъекции через данные товара и предпросмотр в админке | textContent/DOM вместо интерполяции HTML, экранирование атрибутов |
| Непроверенные SVG/сертификаты и неограниченные изображения | Проверка формата по содержимому, размеров/пикселей и расширения; безопасный XML, запрет DTD, PI, активных тегов и внешних ресурсов |
| Старые медиа могли обходить новые валидаторы | Команда audit_uploads; nginx ограничивает расширения и добавляет CSP sandbox/nosniff |
| Неограниченные отзывы/поиск/обращения | Ограничения длины полей, поиска, размера тела и числа полей |
| Спам форм и перебор входа | Отдельные лимиты POST в nginx, 429, IP из соединения; GET не ограничиваются этим лимитом |
| Ненадёжный HTML и слишком длинные уведомления Telegram | Ограниченный обычный текст; полная заявка остаётся в БД; ошибки не раскрывают токен или текст API-ответа |
| Обход nginx через публичный Gunicorn и доверие forwarded-заголовкам | Production без опубликованного 8000; nginx перезаписывает заголовки; X-Forwarded-Host не используется |
| Лишняя публикация служебных сервисов | База/Adminer только loopback, Adminer по запросу, Certbot в production-профиле |
| Секреты и окружение попадали в Docker build context | .dockerignore; проверено отсутствие .env в финальном образе |
| Приложение работало root | UID/GID 1000, запрет повышения привилегий и сброшенные capabilities |
| Известные CVE в семи закреплённых Python-зависимостях | Обновлены certifi, idna, Pillow, python-dotenv, requests, sqlparse, urllib3; повторный pip-audit без исключений |
| Уязвимые системные пакеты и встроенные библиотеки pip/uv/gosu | Alpine runtime, системные обновления, удалены менеджеры пакетов из runtime, gosu заменён su-exec; исправлены все пять образов |
| Не работала статика локально | Отдельный HTTP override nginx; сайт и CSS доступны через localhost |

Настройки production включают HTTPS redirect, Secure/HttpOnly cookie, HSTS на год, DENY для iframe и защитные заголовки. Локальный override явно включает отладку и допускает HTTP-cookie только для локального запуска.

## Результаты проверки

- 31 тест успешно пройден на SQLite и повторно на PostgreSQL в отдельной тестовой базе. Тестовые базы удалены штатно Django.
- `pip check` при сборке: конфликтов зависимостей нет. `pip-audit` закреплённых и фактически установленных пакетов: известных уязвимостей не найдено.
- Trivy проверил все уровни серьёзности без ignore-файлов и без `--ignore-unfixed`:

- Production guard checks: DEBUG=False действительно выключает отладку, включаются HTTPS/cookie/HSTS; слабый ключ и wildcard-хост приводят к отказу старта.
- HTTP smoke: главная, каталог, сертификаты, отзывы, юридические страницы, health, CSS и логотип возвращают 200. Защитные заголовки присутствуют. Некорректные POST без CSRF сначала возвращают 403, после лимита — 429. Подмена X-Forwarded-For не обходит лимит. Вход имеет отдельный лимит, GET продолжают работать.
- `audit_uploads`: локальных загруженных файлов 0, непроверенных файлов нет.
- Миграции применены, расхождений моделей и миграций нет, nginx -t успешен. PostgreSQL healthy. Приложение работает без root и без pip; .env в образе отсутствует.
- Certbot --version проверен при сборке. Реальное получение/обновление сертификатов не запускалось.

## Границы результата

Нулевое число известных CVE относится к проверенным образам и базам сканеров на дату проверки. Это не гарантия отсутствия неизвестных уязвимостей и не аудит ядра/настроек Docker-хоста.

У `check --deploy` остаются два осознанных предупреждения о HSTS includeSubDomains и preload. Они не включены без проверки HTTPS всех поддоменов и готовности владельца к preload; обычный HSTS включён. Предупреждения не скрыты.

Публичный HEAD-запрос к https://bezvreda05.ru/ вернул 200, но в ответе рабочего сервера отсутствовал Strict-Transport-Security. Это подтверждает необходимость отдельно применить подготовленные изменения на сервере. Его файловая система, firewall, роли БД, резервные копии и действующие секреты не проверялись без доступа к окружению. Секреты из ранее опубликованных образов нужно отозвать у провайдера, если такие образы публиковались; локальное исправление не отзывает токены.

Проверка PDF по заголовку не является антивирусной проверкой; загрузка доступна через админку, медиа изолированы CSP sandbox. Лимиты IP уменьшают спам, но не заменяют защиту от распределённой атаки. Эти ограничения учтены в инструкции эксплуатации.
